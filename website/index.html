gatecheck

Fail the build when security scan results cross your thresholds.

Gatecheck reads a scanner report, compares it with the limits in a config file, and exits non-zero when a limit is crossed. One binary. Nothing to host.

Install command

$ go install github.com/gatecheckdev/gatecheck/cmd/gatecheck@latest
Docs GitHub

Needs Go 1.23 or newer. Prebuilt binaries for Linux, macOS, and Windows are on the releases page.

Example

How it works

  1. 01

    A scanner writes a report

    Grype, CycloneDX, Semgrep, Gitleaks, or a coverage file. Gatecheck picks the type from the filename.

  2. 02

    You set the thresholds

    gatecheck config init prints a config with the limits off. Turn on the ones you mean to enforce. 

    grype:
  severityLimit:
    critical:
      enabled: true
      limit: 0
    high:
      enabled: true
      limit: 5

  3. 03

    CI passes or fails

    gatecheck validate -f gatecheck.yaml grype-report.json exits 1 when a limit is crossed, and 0 when the report is inside it.

What it checks

list (alias ls) prints a table. download epss and download kev print the datasets to stdout. Command details are in the docs.

  • Grype

    Severity counts, a CVE deny list, and a list of accepted CVEs.

  • CycloneDX

    The same CVE checks for vulnerabilities in a CycloneDX SBOM.

  • Semgrep

    Limits for error, warning, and info findings.

  • Gitleaks

    Fail when the report contains secrets.

  • Coverage

    Line, function, and branch thresholds for LCOV, Clover, and Cobertura.

  • Bundles

    bundle create and bundle add pack reports into one gzipped archive with a manifest.

  • EPSS

    FIRST scores on list --epss for Grype and CycloneDX, and a score limit during validate.

  • KEV

    Fail validate when a CVE is in the CISA known-exploited catalog.

In CI

A non-zero exit fails the job. The report filename has to contain the type, such as grype or semgrep. 

- name: Validate the Grype report
  run: gatecheck validate -f gatecheck.yaml grype-report.json
